# Success Metrics

This document defines the quantitative KPIs and qualitative success criteria for the Great Commission Benchmark.

---

## Qualitative Success Vision

A successful Great Commission Benchmark means:

- **Christian organizations** can quickly identify which LLMs best support their work
- **Volunteers** can easily contribute by testing models they care about
- **The community** sustains itself through sponsorship and contributions
- **Model developers** have clear feedback on how to better serve this user segment
- **The broader conversation** about religious freedom in AI advances with evidence

---

## Quantitative KPIs

### Core Metrics

| Metric | Description | Target |
|--------|-------------|--------|
| **Models tested** | Total unique models on the leaderboard | Comprehensive coverage of relevant models |
| **Monthly visitors** | Unique monthly visitors to the website | Steady growth |
| **Benchmark runs** | Total completed test runs | ~600 lifetime |
| **Organizations aware** | Christian orgs referencing the benchmark | Broad recognition |

### Engagement Metrics

| Metric | Description | Target |
|--------|-------------|--------|
| **Sponsorship requests** | Users requesting sponsored tests | Healthy demand |
| **Voluntary donations** | Tips and contributions received | Cost-neutral |
| **Newsletter subscribers** | Community members following updates | Growing list |
| **Result shares** | Social media/link shares of results | Organic spread |

### Quality Metrics

| Metric | Description | Target |
|--------|-------------|--------|
| **Review completion rate** | % of results with human review | > 80% |
| **Inter-rater reliability** | Judge accuracy vs. calibration | ≥ 80% |
| **User satisfaction** | Feedback on testing experience | Positive |
| **Refund rate** | % of tests resulting in refunds | < 5% |

## Tracking Plan

### Models Tested

**What to track:**
- Total unique models on leaderboard
- Models per category (commercial, open-source)
- Coverage of major AI providers
- New models added per quarter

**How to track:**
- Database query on unique model entries
- Dashboard showing coverage

**Target progression:**
| Phase | Models |
|-------|--------|
| Launch | 5-10 |
| 6 months | 20-30 |
| 1 year | 40-50 |
| Ongoing | All relevant models |

### Monthly Visitors

**What to track:**
- Unique visitors per month
- Page views
- Time on site
- Traffic sources

**How to track:**
- Privacy-respecting analytics (Plausible, Fathom, or simple server logs)
- No invasive tracking

**Target progression:**
| Phase | Monthly Visitors |
|-------|------------------|
| Launch | 100-500 |
| 6 months | 500-1,000 |
| 1 year | 1,000-2,500 |
| Mature | 2,500+ |

### Organizations Aware

**What to track:**
- Organizations citing the benchmark
- Mentions in newsletters, articles, presentations
- Direct inquiries from organizations
- Partnership discussions

**How to track:**
- Google Alerts for benchmark mentions
- Manual tracking of citations
- Inquiry log

**Target progression:**
| Phase | Awareness |
|-------|-----------|
| Launch | Founding partners |
| 6 months | 10-20 organizations |
| 1 year | 50+ organizations |
| Mature | Recognized standard |

## Financial Sustainability Metrics

### Revenue Tracking

| Metric | Description |
|--------|-------------|
| **Test revenue** | Processing fees collected |
| **Tips received** | Voluntary contributions |
| **Sponsorships** | Tests funded for others |
| **Donations** | General fund contributions |

### Cost Tracking

| Metric | Description |
|--------|-------------|
| **Infrastructure costs** | Railway, Auth0, domain |
| **API cost pass-through** | OpenRouter charges |
| **Stripe fees** | Payment processing |
| **Cost per test** | Total cost / tests completed |

### Sustainability Goal

**Break-even:** Total revenue ≥ Total costs

- Processing fees cover operational costs
- Tips and donations provide buffer
- Sponsoring project backstops shortfalls

## Benchmark Quality Metrics

### Cross-Version Analysis

| Metric | Purpose |
|--------|---------|
| **Version coverage** | Models tested across multiple versions |
| **Score stability** | How consistent are scores across versions |
| **Question effectiveness** | Do questions differentiate well |
| **Methodology improvement** | Are newer versions more reliable |

### Result Quality

| Metric | Target |
|--------|--------|
| **Inter-rater reliability** | ≥ 80% |
| **Reproducibility** | ≥ 95% |
| **Differentiation** | Meaningful variance |
| **Review coverage** | > 80% of results reviewed |
