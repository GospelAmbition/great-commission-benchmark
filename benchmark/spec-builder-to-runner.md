# Specification: Builder to Runner Distribution

This document specifies how benchmark versions from the GCB Builder CLI get compiled and distributed to the GCB Runner CLI.

---

## Overview

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                       BUILDER TO RUNNER FLOW                                 │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│   GCB Builder CLI          Compile Step            GCB Runner CLI           │
│   ───────────              ────────────            ──────────               │
│                                                                             │
│   ┌─────────────┐         ┌─────────────┐         ┌─────────────┐          │
│   │  Publish    │         │  Compile    │         │  Embedded   │          │
│   │  Version    │ ──────▶ │  Bundle     │ ──────▶ │  in PyPI    │          │
│   │             │         │             │         │  Package    │          │
│   └─────────────┘         └─────────────┘         └─────────────┘          │
│         │                       │                       │                   │
│         ▼                       ▼                       ▼                   │
│   gcb-v2.0.json           v2_0/bundle.py          pip install               │
│   (JSON export)           (Python module)         gcb-runner                │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

**Key difference from Builder → Platform flow:**
- Platform: Questions uploaded via web, stored in database, served via API
- Runner: Questions compiled into Python package, distributed via PyPI

## Threat Model

### What We're Protecting Against

**Training data contamination** — AI labs systematically scraping benchmark questions to include in training data, which inflates scores without improving actual capability.

| Vector | Risk | Mitigation |
|--------|------|------------|
| Public API endpoint | High | No API endpoint for questions |
| Web scraping | High | Questions never on web pages |
| CommonCrawl / web archives | High | Questions embedded in PyPI package |
| Automated PyPI extraction | Medium | Light obfuscation (not plaintext) |
| Manual reverse engineering | Low | Accepted risk (yearly version rotation) |

### What We're NOT Protecting Against

- **Individual testers cheating** — Low concern; no financial incentive
- **Determined reverse engineering** — Accepted; questions aren't exam answers
- **Memory inspection during runs** — Unavoidable in client-side execution

### Security Philosophy

We use **light obfuscation** (compression + encoding), not encryption. This is:
- Honest about its limits
- Sufficient to prevent bulk scraping
- Simple to implement and maintain

Questions will eventually leak. Yearly version rotation limits exposure.

## Bundle Format

Questions are compiled into Python modules:

```python
# gcb_runner/versions/v2_0/bundle.py

"""
GCB Benchmark V2.0 - Question Bundle
Generated: 2025-12-01T00:00:00Z
Checksum: sha256:abc123...

DO NOT MODIFY - Auto-generated by gcb-compile-bundle.
"""

import base64
import zlib
import json

# Metadata (visible)
VERSION = "2.0"
RELEASE_DATE = "2025-12-01"
QUESTION_COUNT = 300
TIER_DISTRIBUTION = {"tier1": 210, "tier2": 60, "tier3": 30}
CHECKSUM = "sha256:abc123def456..."

# Question data (compressed + base64 encoded)
_BUNDLE_DATA = """
eJzVWNtu2zgQfV9g/4HwS+ILJUq2nTgI0KJFs0WLLrZAi32gKMoWI4kCScV2...
"""

def _decode_bundle() -> dict:
    """Decode the question bundle."""
    compressed = base64.b64decode(_BUNDLE_DATA.strip())
    json_bytes = zlib.decompress(compressed)
    return json.loads(json_bytes)
```

### What's Included in Bundle

| Component | Purpose |
|-----------|---------|
| Questions | All 300 questions with metadata |
| Judge prompts | Tier-specific evaluation prompts |
| Scoring config | Weights, formulas |
| Checksum | Integrity verification |

### What This Achieves

✅ **Prevents casual browsing** — `cat bundle.py` shows encoded blob  
✅ **Blocks web scrapers** — Questions never served via HTTP  
✅ **Works offline** — No network dependency  
✅ **Version stability** — Each CLI release has immutable questions  

❌ **Does not prevent** determined extraction (accepted tradeoff)

## Compilation Process

### Step 1: Builder Exports JSON

```bash
$ gcb-builder publish

✓ Validating v2.0...
✓ Export created: gcb-v2.0.json (48 KB)
```

Output: Standard JSON export (same format as Platform uploads)

### Step 2: Compile to Python Bundle

```bash
$ gcb-compile-bundle gcb-v2.0.json --output gcb-runner/gcb_runner/versions/v2_0/

✓ Compiled V2.0 to gcb_runner/versions/v2_0/
  Questions: 300
  Checksum: sha256:abc123...
```

The compile script:
1. Reads JSON export
2. Computes SHA-256 checksum
3. Compresses with zlib (level 9)
4. Encodes as base64
5. Generates `bundle.py` with metadata + encoded data
6. Creates `__init__.py`

### Step 3: Update Version Registry

```python
# gcb_runner/versions/loader.py

AVAILABLE_VERSIONS = {
    "1.0": "gcb_runner.versions.v1_0",
    "1.1": "gcb_runner.versions.v1_1",
    "2.0": "gcb_runner.versions.v2_0",  # ← Add new version
}

CURRENT_VERSION = "2.0"  # ← Update if this is the new default
```

### Step 4: Release CLI

```bash
# Bump version
# pyproject.toml: version = "1.4.0"

# Publish to PyPI
python -m build
twine upload dist/*
```

## Compile Script Reference

The `gcb-compile-bundle` script can live in gcb-builder or as a standalone tool:

```python
#!/usr/bin/env python3
"""Compile JSON question export to Python bundle for gcb-runner."""

import argparse
import base64
import hashlib
import json
import zlib
from datetime import datetime
from pathlib import Path


def compile_bundle(input_path: Path, output_dir: Path) -> None:
    """Compile a JSON question set export into a Python bundle."""
    
    with open(input_path) as f:
        data = json.load(f)
    
    version = data["benchmark_version"]
    
    # Compute checksum of full data
    checksum = hashlib.sha256(
        json.dumps(data, sort_keys=True).encode()
    ).hexdigest()
    
    # Compress and encode
    json_bytes = json.dumps(data).encode()
    compressed = zlib.compress(json_bytes, level=9)
    encoded = base64.b64encode(compressed).decode()
    
    # Generate bundle.py
    bundle_code = f'''"""
GCB Benchmark V{version} - Question Bundle
Generated: {datetime.utcnow().isoformat()}Z
Checksum: sha256:{checksum}

DO NOT MODIFY - Auto-generated by gcb-compile-bundle.
"""

import base64
import zlib
import json
from typing import Any

VERSION = "{version}"
RELEASE_DATE = "{data.get('locked_at', '')[:10]}"
QUESTION_COUNT = {len(data['questions'])}
TIER_DISTRIBUTION = {data['metadata']['tier_counts']}
CHECKSUM = "sha256:{checksum}"

_BUNDLE_DATA = """
{encoded}
"""

def _decode_bundle() -> dict[str, Any]:
    """Decode the question bundle."""
    compressed = base64.b64decode(_BUNDLE_DATA.strip())
    json_bytes = zlib.decompress(compressed)
    return json.loads(json_bytes)
'''
    
    # Write files
    output_dir.mkdir(parents=True, exist_ok=True)
    
    (output_dir / "__init__.py").write_text(
        f'"""GCB Benchmark V{version}"""\n'
    )
    (output_dir / "bundle.py").write_text(bundle_code)
    
    print(f"✓ Compiled V{version} to {output_dir}")
    print(f"  Questions: {len(data['questions'])}")
    print(f"  Compressed: {len(json_bytes)} → {len(compressed)} bytes")
    print(f"  Checksum: sha256:{checksum[:16]}...")


if __name__ == "__main__":
    parser = argparse.ArgumentParser(description="Compile GCB question bundle")
    parser.add_argument("input", type=Path, help="JSON export file")
    parser.add_argument("--output", "-o", type=Path, required=True,
                        help="Output directory for bundle")
    
    args = parser.parse_args()
    compile_bundle(args.input, args.output)
```

## CLI Release Process

### Version Numbering

The CLI uses semantic versioning (MAJOR.MINOR.PATCH):

| Change Type | Version Bump | Example |
|-------------|--------------|---------|
| New benchmark version added | MINOR | 1.2.0 → 1.3.0 |
| Bug fixes only | PATCH | 1.3.0 → 1.3.1 |
| Breaking API/export format changes | MAJOR | 1.3.0 → 2.0.0 |
| New CLI features (non-breaking) | MINOR | 1.3.0 → 1.4.0 |

**Note:** Adding a new benchmark version is always a MINOR bump, even if it's a major benchmark milestone (e.g., Version 1 → Version 2).

### Release Steps

```bash
# 1. Ensure clean working directory
git status  # Should be clean or only have release changes

# 2. Update version in pyproject.toml
# [project]
# version = "1.4.0"

# 3. Update CHANGELOG.md
# ## [1.4.0] - 2025-12-17
# ### Added
# - Benchmark Version 2 (2.0) - new question set with updated categories
# ### Fixed
# - (any bug fixes)

# 4. Commit release changes
git add pyproject.toml CHANGELOG.md gcb_runner/versions/
git commit -m "Release v1.4.0 - Add Benchmark Version 2"

# 5. Tag the release
git tag -a v1.4.0 -m "Release v1.4.0"

# 6. Build distribution packages
rm -rf dist/  # Clean previous builds
python -m build

# 7. Verify the build
ls dist/
# gcb_runner-1.4.0-py3-none-any.whl
# gcb_runner-1.4.0.tar.gz

# 8. Test the built package (optional but recommended)
pip install dist/gcb_runner-1.4.0-py3-none-any.whl --force-reinstall
gcb-runner --version
gcb-runner versions

# 9. Upload to PyPI
twine upload dist/*

# 10. Push to git
git push origin main
git push origin v1.4.0
```

### Post-Release Verification

```bash
# 1. Verify PyPI listing
# Visit https://pypi.org/project/gcb-runner/

# 2. Test fresh install
pip uninstall gcb-runner
pip install gcb-runner
gcb-runner --version  # Should show new version
gcb-runner versions   # Should list new benchmark

# 3. Quick smoke test
gcb-runner test --model gpt-4o --benchmark-version 2.0 --dry-run
```

### Rollback Procedure

If a release has critical issues:

```bash
# 1. Yank the bad release on PyPI (hides but doesn't delete)
# Go to PyPI → Manage Project → Release → Options → Yank

# 2. Fix the issue locally

# 3. Bump to next patch version (never reuse version numbers)
# 1.4.0 (yanked) → 1.4.1 (fixed)

# 4. Release the fix following normal release steps
```

**Important:** Never delete a PyPI release or reuse a version number. Yank and release a new patch version instead.

### Release Frequency

| Release Type | Typical Frequency | Trigger |
|--------------|-------------------|---------|
| Benchmark version update | ~Yearly | New question set finalized |
| Bug fix release | As needed | Critical bugs reported |
| Feature release | Quarterly | New CLI capabilities |

## Version Compatibility

| CLI Version | Bundled Benchmark Versions | Notes |
|-------------|---------------------------|-------|
| 1.0.0 | 1.0 | Initial release |
| 1.1.0 | 1.0, 1.1 | Added benchmark 1.1 |
| 1.2.0 | 1.0, 1.1, 1.2 | Added benchmark 1.2 |
| 1.3.0 | 1.0, 1.1, 1.2, 2.0 | Major benchmark update |

**Policy:** New CLI versions add benchmark versions, never remove them. Users can always run older benchmarks for comparison.
